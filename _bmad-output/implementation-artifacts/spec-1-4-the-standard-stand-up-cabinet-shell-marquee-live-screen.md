## Intent

**Problem:** The authored room has 20 Wall Slots and baseplates but no cabinet stands in it — the collision-volume list holds nothing targetable and Story 1.2's `registerInteractable` registry is still empty. The fiction's core noun, the Cabinet ("Carries marquee, attract mode, coin door, Instruction Card" — glossary), does not exist in the world; Story 1.5 cannot seat Moon Patrol "in place" and 1.6 cannot have one busy machine until a standard shell with a title marquee, a live screen, and an E-openable coin door occupies a slot.

**Approach:** Author exactly ONE stand-up shell — Moon Patrol's, in slot B0, the composition `mockups/cabinet-close-up.html` draws — entirely inside the systems 1.3 already built: a new authored-data module `core/room/cabinets.ts` (shell spec, one placement, screen-zone strings, coin-door state, attract phase) beside its siblings; one `cabinet-B0` entry in the single collision-volume list, exactly as that module's comment already predicts; the existing scene builder assembles the shell parts through the existing Three seam (extended, not forked); marquee/screen painters extend `surfaces.ts` beside `paintFlyer`; and `core/main.ts` wires the E handler into the player's existing interact registry plus a "cabinets" kernel system that advances screen motion inside the tick. Zero new dependencies, zero DOM, zero games imports; the screen is alive by kernel phase, never by wall clock.

## Boundaries & Constraints

**Always:** the single volume list at `core/room/collision-volumes.ts` stays the one source for the cabinet too — blocking, targetability, (Epic 2) occlusion, and the body mesh extrusion all come from that entry (spine "Room geometry & collision" row; the kind `"cabinet"` already exists in `VolumeKind`, and the module comment says 1.4's shells enter "as targetable cabinet volumes": blocksMovement true, targetable true). Shell furniture is hard-cornered boxes only (mockup: `rounded.cabinet 0px`): body footprint 0.60m × 0.60m (room-layout's stand-up contract) on the authored baseplate anchor, marquee bar, screen bezel + face, coin-door panel, coin-slot detail — the mockup's stacked composition, token use only, never render fidelity (UX-DR26). Marquee lettering is ONLY the game-title record, uppercased — "MOON PATROL" (the mockup's string on this exact composition; cabinet-inventory: Moon Patrol is "already built — first v1 machine") — never a model name, badge, or tagline (FR-9 partial, UX-DR2/UX-DR5); glow-marquee amber on Room Black; cap height floor 0.18m, "never smaller than authored cap height" (DESIGN typography frontmatter); declared kind `marquee` in the AD-24 whitelist home. The screen is a Core-owned surface treatment (UX-DR6) in the era-CRT voice: attract zone (title + a phase-shifted low-frequency scan-band drift) and a steady NEXT zone at the marquee's authored 0.18m minimum, glowing in the cabinet's own hue family (glow-cyan — the mockup marks its attract title and halo as this game's family); the score zone renders nothing until scores exist (no fabricated rows — CAP-8 "no fake strangers"). Liveness law: attract phase advances only via a `loop.addSystem("cabinets")` kernel system (AD-3, AD-15); `frame()` reads the phase from cabinet state — never `loop.tickCount`, never a clock (main-glue's frame() bans those strings); the screen repaints only when its paint step changes, then the seam marks the texture updated. Coin door: E while the cabinet is targeted toggles open/closed; state mutates only inside the tick (the handler runs from `player.step`); pose law — closed flush with the body front, open swung 90° out about the panel's left vertical hinge, deterministic position+rotation math; the Instruction Card behind it is Epic 3 — the recess stays dark. Font: paint with the CSS stack `"Chakra Petch","Saira Condensed","Arial Narrow",sans-serif` (DESIGN's provisional face + its own ASSUMPTION fallback; the mockup itself is "Bahnschrift sim, no webfont... zero external requests") — no webfont vendoring, no new dependency, sealed build makes zero external calls (AD-18). Every new surface colour is a `tokens.ts` hex. All authored numbers that are not contract values are labelled (inference), "tuned by eye at the smoke" (1.3 precedent).

**Never:** no game plugins, no `games/**` imports, no registry entries (generated registry stays 0 — AD-1, registry-drift gate); no second shell and no hand-built wall (SPEC non-goal: the rest of the 22-cabinet inventory is "grown by the pipeline, never a hand-built v1 wall") — exactly one shell, and the other 19 slots keep their empty baseplates so the roadmap wall still reads; no Instruction Card surface (Story 3.5); no Layout System fill function (AD-10 — 3.4 derives placements then; this story authors a placement record, room data); no edits to `core/player.ts` step/target/interact semantics or `core/loop.ts` (only their data and wiring consume them); no new dependencies, no webfont files, no DOM text surfaces; no `Math.random`/`Date.now`/`performance.now` in any new code; no legibility/flash lint in CI (Epic 3 L0–L2 — the 0.18m cap and ~15m legibility bind as pinned values plus the lead's smoke call now).
