## Intent

**Problem:** Scores die with the page. The `scoreSubmitted` event already flows through the kernel chain (1.5 pair, 1.6 single-drainer law), but nothing downstream keeps it: no visitor identity exists (no core module touches `localStorage`), no Personal Best survives a reload, Patron autoplay runs are invisible outside the scheduler, and the 1.4 score zone (`cabinets.ts:58-65`, surfaces.ts drawScreen:371-383) is lawfully empty — "renders nothing until Story 1.8 fills it."

**Approach:** Land the spine's storage/identity service (`core/storage.ts`, the SVC box): a boot-time anonymous UUIDv4 in `localStorage` under `arcade.*`, Personal Bests keyed `(stable gameId, visitorId)`, a runtime Patron-run table fed by an ingest leg riding the patrons system's existing single drain, kernel-derived pseudonyms for missing initials, and a `rowsFor(gameId)` read that the shipped frame() feeds into the EXISTING score-zone painter path — on the fallback face, where the painter YIELDS the attract block when the score zone has rows (AD-28; lead measurement 2026-11-24, executed against the real painter + authored B0 data: the 0.44x0.52m face fits AT MOST 2 rows under the live scan band — baselines 177/309 — and zero rows while the attract block stands). The sim half stays ignorant: the table never enters tick input, snapshot, or stateHash.

**Acceptance Criteria:**

**AC 1 — Anonymous identity, no account, no PII (FR-7, AD-16, NFR-5).** Given empty storage, when the service boots, then exactly one key `arcade.visitor` holds a UUIDv4 (shape-validated), written once; given a second service over the same storage (the reload), then the same id is read back without rewrite; nothing else about the visitor exists anywhere (no other key, no DOM, no prompt).

**AC 2 — Scores travel only via `scoreSubmitted`; the kernel owns the table (AD-6, AD-16).** Given a drained `scoreSubmitted {score, initials?}`, when ingest classifies it (scheduler occupancy: patron-autoplay → Patron run with initials derived from the run's resolved seed; visitor-seated → PB; idle → recorded neither), then the visitor path updates the Personal Best iff the score beats it (higher-wins at M0 — label); game-supplied initials sanitize to ≤3 chars A–Z; missing initials get the kernel pseudonym; no file under `games/**` changed and the sim's tick input stays `{controls}` — the sim never reads, branches on, or stores table content (M0 review enforcement; L0 red lands Epic 3).

**AC 3 — The table renders read-only in the presentation half, with the content law (FR-7, UX-DR6).** Given an empty table, then `rowsFor` is `[]` and the score zone renders nothing (the 1.4 CAP-8 pins green); given Patron runs but no Personal Best, then rows are Patron runs alone; given a Personal Best, then rows lead with the PB row; the composed zones feed `repaintScreen` on the fallback face (main-glue pins: boot identity, ingest leg inside the patrons body, composed-zone argument); with rows present the fallback face yields the attract title block and paints at most the cap-2 rows under the live scan band (AD-28), pinned at the surfaces tier alongside the unchanged empty-zone law.

**AC 4 — Returning shows the Personal Best keyed (stable gameId, visitorId) (FR-7, seeds FR-16).** Given a visitor scored run persisted under `arcade.pb.<visitorId>.<gameId>`, when a fresh service (same storage) computes rows, then the PB row appears with the same initials — the same key carries refurbish continuity (AD-9 stable gameId).

**AC 5 — The 1.7 laws do not regress; a quarantined Cabinet keeps its table law.** Given `injectFault` then 720 ticks, then no new table row ever appears (the guard emits no events), `rowsFor` stays byte-stable, and the fallback face keeps painting the current rows through paint steps (attract yields while rows exist — AD-28 — and never throws: with ≤2 rows the fit law guarantees a clean paint every step); all 1.4 empty-zone and 1.7 containment/seat/scheduler pins byte-unchanged; exactly one `drainEvents()` call site remains in main.ts.

**AC 6 — Bounded, hermetic, green suite.** Patron rows capped (cap-2 view, ring-bounded); a throwing storage write degrades to in-memory with zero faults and the loop ticking on; `npm test` (298 baseline at HEAD 315c998 + new), `npm run typecheck`, `node ci/depcheck.mjs`, `node ci/lint-bans.mjs`, registry regen no-drift, `npm run build` all green; zero new dependencies; zero outbound calls beyond the never-shipped `/api/report` (AD-18).
